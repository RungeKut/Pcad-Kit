# Dbx32.dll — только 32 бита

## Что происходит

`Dbx32.dll` собрана под x86. Из 64-битного процесса (в том числе любого
современного Python) она не загружается: `LoadLibrary` даёт
«%1 is not a valid Win32 application».

## Почему

Windows не смешивает разрядность внутри процесса. P-CAD 2002 64-битной
версии не существует.

## Как правильно

Вызовы DBX выносить в x86-процесс. В наборе это `tools/dbx-host/DbxHost.cs`,
собирается штатным `C:\Windows\Microsoft.NET\Framework\v4.0.30319\csc.exe`
с `/platform:x86` (ставить ничего не нужно, .NET Framework 4 есть на любой
Windows). Python общается с ним по JSON через stdin/stdout (10-02).

В C#-обёртке: `CallingConvention.StdCall`, `StructLayout(Pack=1)`,
строки `ByValTStr` ANSI (кириллица — cp1251 системной локали).

## Как неправильно

* Ставить 32-битный Python ради ctypes — лишняя среда, а разрядность
  интерпретатора потом будет путаться с основной.
* `Assembly.LoadFile("Dbx32.dll")` — native DLL так не грузится
  (в PCAD_SCH_Editor этот мёртвый метод остался как напоминание).

## Чем подтверждено

`tools\dbx-host\build.bat` + `poc.py`: x86-хелпер подключился к Sch.exe
и выгрузил схему под 64-битным Python 3.14.
