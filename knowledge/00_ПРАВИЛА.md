# Правила базы знаний

1. **Достоверность важнее объёма.** Хранится только то, что нельзя получить
   быстрее другим способом. Критерий: «если не записать — потеряет ли
   следующая сессия больше 10 минут».
2. **Приоритет: опыт важнее документации.** Dbx32.h/ACCELDBX.doc описывают
   задумку; база фиксирует, что реально произошло на этой машине.
3. **Структура:** `10_API` (как вызывать), `20_ПРИЁМЫ` (как работать),
   `30_ГРАБЛИ` (что ломается — каждая запись = потерянный час), `40_СРЕДА`
   (установка, версии). Один файл — одна тема, предел ~200 строк.
4. **Нумерация:** `РАЗДЕЛ-НН_короткое_имя.md`. Номер выдаётся внутри раздела
   и не переиспользуется после удаления; занятые — внизу INDEX.md.
5. **Шапка YAML обязательна** (id, title-утверждение, tags, applies_to с
   версией, status, verified — как именно проверено, source). Запись без
   `verified` силы не имеет.
6. **Шаблон тела:** `# Заголовок` → `## Что происходит` → `## Почему` →
   `## Как правильно` (рабочий код целиком) → `## Как неправильно`
   (обязателен для 30_ГРАБЛИ) → `## Чем подтверждено`.
7. **Цикл добавления:** файл → строка в INDEX.md → строка в CHANGELOG.md.
8. **Обезличивание:** в набор не попадает ничего об изделии — ни названий,
   ни децимальных номеров, ни имён цепей/компонентов изделия, ни путей
   проектов. Примеры — на отвлечённой схеме.
9. При смене поведения старое утверждение не стирается, а уходит в раздел
   «История» с датой.
10. Язык — русский; идентификаторы и код — латиница.
11. Версия: база собрана на P-CAD 2002 (V17.01.22, DBX 16.000). На другой
    версии запись «проверено» читается как «не проверено».
